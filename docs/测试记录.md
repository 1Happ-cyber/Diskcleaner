## 五、回收站与 exe 的实际验证

**exe 已验证**：`dist/DiskCleaner/DiskCleaner.exe`（目录版 27 MB，压缩包 12.4 MB；官方 Python 3.14 + Tk 8.6 打包）在本机双击/命令行启动成功，窗口标题为“磁盘占用分析与安全清理 · v0.2.0”，界面可正常显示。未在“没有安装 Python 的机器”上复验，这一步需本人完成。

**单文件版在本机的限制**：`build.bat onefile` 生成的单文件 exe 启动时报 `Could not create temporary directory!`。原因是单文件版运行时要把自身解压到 `%TEMP%`，而本机桌面会话禁止子进程在工作区之外创建目录/文件（同一次会话里，`send2trash` 也出现“文件消失但回收站无记录”的同类拦截）。因此交付默认改为**目录版**，它不需要运行时解压。程序另外增加了数据目录可写性探测：`%LOCALAPPDATA%` 不可写时自动回退到程序目录下的 `DiskCleanerData`，并在信息页注明。

**回收站验收脚本已加强**：旧版只看“原文件是否消失”，这在文件被永久删除时也会显示通过。现在 `scripts/verify_recycle.py` 会额外扫描 `$Recycle.Bin` 里最近删除的 `$I`/`$R` 记录，只有找到**内容完全一致**的 `$R` 文件才判定“已移入回收站”。

**本会话中的实测结果（重要）**：在 AI 开发会话的受限进程里执行脚本，`send2trash` 返回成功、原文件消失，但回收站中找不到对应记录——脚本因此判定失败（退出码 1）。这说明：
- 脚本的核对逻辑是有效的，不会把“永久删除”误报为“安全回收”；
- 该会话进程受到环境限制，**不能**作为回收站验收的代表；
- 需在**普通命令行或资源管理器**中重跑一次，才是真实验收结论。

```powershell
python scripts\verify_recycle.py --dir .\验收样本 --open
```

预期：输出“回收站中是否找到同内容样本：是”，回收站里出现“待清理样本.txt”，恢复后内容为“可丢弃的验收样本。用于确认文件进入回收站后仍可恢复。”。
